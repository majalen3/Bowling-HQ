# Versioning & Release Guide\n\n## Versioning Strategy\n\nBowling HQ uses **Semantic Versioning** (MAJOR.MINOR.PATCH):\n\n- **MAJOR**: Breaking changes\n- **MINOR**: New features (backward compatible)\n- **PATCH**: Bug fixes\n\nExample: `1.2.3`\n\n## Release Process\n\n### 1. Prepare Release\n\n```bash\n# Update version in package.json / setup.py\n# Update CHANGELOG.md\n# Commit changes\ngit add CHANGELOG.md package.json\ngit commit -m \"Bump version to 1.2.3\"\n```\n\n### 2. Create Release Branch\n\n```bash\n# Create release branch\ngit checkout -b release/1.2.3\n\n# Run final tests\nmake test\n\n# Build for production\nmake build\n```\n\n### 3. Tag Release\n\n```bash\n# Create annotated tag\ngit tag -a v1.2.3 -m \"Release version 1.2.3\"\n\n# Push tag\ngit push origin v1.2.3\n```\n\n### 4. GitHub Release\n\n```bash\n# Create release on GitHub\n# Title: Release v1.2.3\n# Description: Include changelog highlights\n# Attach build artifacts\n```\n\n### 5. Deploy\n\n```bash\n# Deploy to staging\nmake deploy-staging\n\n# Run smoke tests\nmake test-smoke\n\n# Deploy to production\nmake deploy-production\n```\n\n## Changelog Format\n\n### Pattern\n\n```markdown\n## [1.2.3] - 2026-07-08\n\n### Added\n- New feature description\n- Another feature\n\n### Changed\n- Modified feature description\n\n### Fixed\n- Bug fix description\n\n### Deprecated\n- Soon-to-be removed feature\n\n### Removed\n- Removed feature\n\n### Security\n- Security fix description\n\n### Known Issues\n- Known issue that still exists\n```\n\n## Version History\n\n### Phase Versioning\n\n- **Phase 0** (0.x.x): Documentation & Design\n- **Phase 1** (1.x.x): Backend Foundation\n- **Phase 2** (2.x.x): Frontend Dashboard\n- **Phase 3** (3.x.x): AI Integration\n- **Phase 4** (4.x.x): Video Analysis\n- **Phase 5** (5.x.x): Advanced Features\n- **Phase 6** (6.x.x): Mobile App\n- **Phase 7+** (7+.x.x): Maintenance & Enhancement\n\n## Deprecation Policy\n\n### Timeline\n\n1. **Announce** (version N): Feature marked as deprecated\n2. **Support** (versions N+1, N+2, N+3): Feature still works with warnings\n3. **Remove** (version N+4): Feature removed entirely\n\n### Example\n\n```python\nimport warnings\n\ndef old_function():\n    warnings.warn(\n        \"old_function is deprecated. Use new_function instead.\",\n        DeprecationWarning,\n        stacklevel=2\n    )\n    # Implementation\n```\n\n## Release Types\n\n### Patch Release (1.2.3 → 1.2.4)\n- Bug fixes\n- Security patches\n- No breaking changes\n- Can be released frequently\n\n### Minor Release (1.2.0 → 1.3.0)\n- New features\n- Backward compatible\n- Released monthly\n- May deprecate features\n\n### Major Release (1.0.0 → 2.0.0)\n- Breaking changes\n- New architecture\n- Feature removals\n- Released yearly\n\n## Pre-release Versions\n\n### Alpha (Early Development)\n```\nv1.3.0-alpha.1\nv1.3.0-alpha.2\n```\n\n### Beta (Stability Testing)\n```\nv1.3.0-beta.1\nv1.3.0-beta.2\n```\n\n### Release Candidate (Final Testing)\n```\nv1.3.0-rc.1\nv1.3.0-rc.2\n```\n\n## Compatibility Matrix\n\n### Supported Versions\n\n| Version | Status | Support Until |\n|---------|--------|---------------|\n| 1.x.x   | Current | 2027-12-31 |\n| 0.x.x   | Legacy | 2026-12-31 |\n\n## Release Notes Template\n\n```markdown\n# Release v1.2.3 - July 8, 2026\n\n## Summary\nBrief description of what's new in this release.\n\n## Features\n- Feature 1 with link to documentation\n- Feature 2 with link to documentation\n\n## Improvements\n- Performance improvement description\n- UX improvement description\n\n## Bug Fixes\n- Bug 1 (closes #123)\n- Bug 2 (closes #456)\n\n## Breaking Changes\n- Breaking change 1 with migration guide\n\n## Deprecations\n- Deprecated feature with replacement\n\n## Migration Guide\n[Link to migration documentation]\n\n## Contributors\n- @contributor1\n- @contributor2\n\n## Installation\n```\nnpm install bowling-hq@1.2.3\n```\n\n## Feedback\nReport issues: [GitHub Issues](https://github.com/majalen3/Bowling-HQ/issues)\n```\n\n## Rollback Procedure\n\n### If Major Issues Found\n\n```bash\n# Revert to previous version\ngit revert <release-commit>\ngit push\n\n# Redeploy previous version\nmake deploy-production VERSION=1.2.2\n\n# Announce rollback\n# Send notification to users\n```\n\n## Version Management\n\n### Files to Update\n\n1. `package.json` - Frontend version\n2. `setup.py` / `pyproject.toml` - Backend version\n3. `CHANGELOG.md` - Release notes\n4. Docker images - Tag with version\n5. API version endpoint - Return current version\n\n### Version Endpoint\n\n```bash\nGET /api/version\n\n{\n  \"version\": \"1.2.3\",\n  \"name\": \"Bowling HQ\",\n  \"released_at\": \"2026-07-08T00:00:00Z\",\n  \"features\": [...]\n}\n```\n\n---\n\n**This is a comprehensive versioning guide for release management.**\n"
