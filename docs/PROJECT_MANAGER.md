# Project Manager Reference

Use this as the single page to keep Bowling-HQ execution moving.

## Purpose

- Run the project like a lightweight PM checklist
- Keep status, decisions, and lessons synchronized
- Always know the next highest-value action

## Start Here Each Session

1. Review [`ADMIN_STATUS.md`](ADMIN_STATUS.md)
2. Review open items in [`DECISIONS_LOG.md`](DECISIONS_LOG.md)
3. Review recent entries in [`LEARNING_LOG.md`](LEARNING_LOG.md)
4. Confirm orchestration rules in [`ADMIN_ORCHESTRATION.md`](ADMIN_ORCHESTRATION.md)

## Daily Operating Loop

1. **Refresh status**
   - Update active work, blockers, dependencies, and risks in [`ADMIN_STATUS.md`](ADMIN_STATUS.md)
2. **Decide next action**
   - Choose the next task with highest readiness and confidence
   - Escalate to strategic planning when confidence is low
3. **Execute and track**
   - Launch/continue workstream
   - Capture key decision in [`DECISIONS_LOG.md`](DECISIONS_LOG.md)
4. **Close loop**
   - Record lesson in [`LEARNING_LOG.md`](LEARNING_LOG.md)
   - Update performance notes in [`AGENT_PERFORMANCE.md`](AGENT_PERFORMANCE.md) when relevant

## Source of Truth Files

- [`ADMIN_STATUS.md`](ADMIN_STATUS.md) — live snapshot: active work, dependencies, blockers, risks
- [`DECISIONS_LOG.md`](DECISIONS_LOG.md) — why major decisions were made
- [`LEARNING_LOG.md`](LEARNING_LOG.md) — what worked, what failed, what changed
- [`AGENT_PERFORMANCE.md`](AGENT_PERFORMANCE.md) — quality/speed trends
- [`LESSONS_LEARNED.md`](LESSONS_LEARNED.md) — reusable patterns and cautions

## Quick Priority Rules

- If dependency is blocked, unblock first
- If risk is high, slow down and validate before launch
- If readiness is low or options compete, escalate for planning input
- If a decision impacts architecture or sequence, log it immediately

## Session Exit Checklist

- [ ] `ADMIN_STATUS.md` reflects current reality
- [ ] New decisions are logged
- [ ] New lessons are captured
- [ ] Next action is explicit and unblocked
